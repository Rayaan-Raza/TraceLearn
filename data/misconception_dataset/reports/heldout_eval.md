## Limitations

- Problem-weighted macro-F1 has a floor here: 6 of 22 problems have no named-class row, and on such a problem a system that never names a class scores 1.0. That is why always-OTHER reaches 0.468. Compare systems with each other and with that floor, not with zero.
- The development set has been scored many times and choices were made with it (EVAL_PROTOCOL section 8); these numbers are development evidence, not an independent test.
- Labels are mostly agent consensus and blind review, treated as human; agreement with them is not accuracy against independent human truth.
- Several classes have under 10 held-out rows and two have none; their per-class figures are not estimates of anything (see the support column).
- Rule stages that read the run record use the 9 Nov second-set cache as their evidence; repairs added after it (for_add_missing_step, range_test_swap_and_or, for_run_downward) never fire here, so a run whose code has them is slightly under-counted.
- A legacy run reports 1.0 for a rule decision (the code before decision_source); its labels, not its confidences, are scored.
