## Which file serves which TraceLearn product

TraceLearn has two deliverables. Each normalized table feeds a different one.

| Table | Student problem set | XGBoost misconception model |
|---|---|---|
| `problems/` | **Primary source.** Use `student_ready=true` rows to build the student-facing problem bank. | Context only. Supplies problem text and tests as features. Not a training target. |
| `submissions/` | Reference solutions only. Use `correct=true` C++ rows as clean exemplars. | **Primary feature source.** Code, verdicts and outcomes feed feature extraction. Labels are still empty. |
| `exclusions/` | No. Audit trail only. | No. Audit trail only. |

### Read this before you build the XGBoost set

`submissions/` gives you **features but no misconception targets**. No local source carries a
CPP-M01 to CPP-M08 label. `tracelearn_label` is null in every row. Human annotation must run
before any supervised training. Do not treat a source verdict as a misconception label.

### Read this before you build the student set

Filter `problems/` on `student_ready=true` to get problems that have both a statement with
sample tests and at least one C++ reference solution. PROGpedia and CodeStream rows do not
set `student_ready`; filter them on `sample_test_count>0` plus a matching `submissions/` row.
